# assembl design

There is one visual source of truth: `docs/assembl-brand-system.md`.
Read it fully, then `DESIGN.md` and `docs/assembl-copy-standard.md` before producing work.
This skill routes to the canon; it does not maintain a second palette or type system.

1. Follow the current user instruction, root `AGENTS.md`, then the canonical files. Do not revive archived or historical directions.
2. Keep the company wordmark lowercase `assembl` and its letter mark lowercase `a`. DO intentionally uses an uppercase D with its small interior dot. Do not mix these identities.
3. Use the canonical Instrument Sans and IBM Plex Mono roles. No serif substitute for company headlines, documents or wordmarks.
4. Use the palette, approved pastel extension, materials and purposeful spatial motion in the current canon.
5. Show a real task, review boundary and useful output. Never let glow, animation or a mock receipt imply external work happened.
6. Use the lightest suitable rendering tier. Real 3D needs a complete static fallback, reduced-motion support, offscreen pause and mobile proof.
7. Reuse the shared DO identity and generation script. Verify browser favicons, app icons, visible chrome and downloads agree.
8. Inspect actual rendered output at desktop and 375px. Run brand, macron, link/route and relevant interaction checks.

The former sea-glass/sage/graphite palette in this skill is superseded. `BRAND-CANON.md` and `COPY.md` are routing pointers; their archived July content is not current instruction.
