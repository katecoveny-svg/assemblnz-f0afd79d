# assembl design system vNext

_Kate's brief, locked 2026-07-10. This is the standing design canon — read it
before touching any surface. When it conflicts with older docs, this wins._

## The single prompt

Do not build a SaaS dashboard. Build the calmest, most intelligent business
operating system ever designed. Every screen should remove cognitive load,
expose only the next meaningful action, and make the user feel that assembl
already understands their business. Design every interaction around the
Business Genome as the single source of truth. Nothing should feel like
separate modules; the website, CRM, knowledge, voice, bookings, automations,
and marketing are all different views of the same living system. If you have
to choose between adding a feature and making the experience simpler, choose
simplicity every time. Prioritise emotional clarity, progressive disclosure,
premium editorial design, cinematic motion, and trust over visual complexity
or AI gimmicks.

Don't make assembl look like an AI product. Make it look like the future of
running a business. If someone can look at a screenshot with the logo removed
and immediately think "I wish every piece of business software felt like
this," we've built something much harder to copy than another agent platform.

## Product philosophy

assembl should never feel like software. It should feel like a calm,
intelligent business partner. Every interaction should reduce cognitive load.
If a screen can lose half of its elements, remove them. If a workflow can
lose half of its steps, remove them.

## Emotional goals

The user should feel: calm · confident · organised · supported · slightly
amazed. Never overwhelmed.

## Visual direction

Editorial minimalism meets living intelligence. Large amounts of whitespace.
Quiet typography. Premium photography only when it tells a story.
Ultra-refined UI. Soft motion. Micro-interactions. No visual noise.

## Colour

Predominantly white. Soft charcoal. One restrained accent colour. Subtle
metallic highlights. No gradients unless they communicate movement.

## Motion

Everything assembles. Nothing pops. Nothing bounces. Particles connect.
Lines grow. Nodes drift. Cards gently emerge. Transitions should feel
cinematic rather than animated.

## Interface principles

One primary action per screen. Maximum clarity. Minimum chrome. Progressive
disclosure. No dashboard should show more than necessary.

## Content

Every word earns its place. Short sentences. Human language. No AI jargon.
No technical language. Never expose implementation details.

## Components — one visual language

Living Site · Business Genome · Morning Brief · Today's Priorities ·
Knowledge · CRM · Bookings · Voice · Insights. Nothing should feel like
separate products.

## Onboarding

Conversation first. Documents second. Generation third. Review fourth.
Live fifth. The user should never feel like they are configuring software —
they should feel like they are introducing assembl to their business.

## Success metric

The product should consistently make users think: **"How did it already know
that?"**
