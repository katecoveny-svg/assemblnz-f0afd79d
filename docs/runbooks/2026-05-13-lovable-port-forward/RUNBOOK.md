### Phase 5 — Casing normalisation (run first after PR #122)

Why first: every other migration assumes lowercase canonical pack and agent_id values. If we INSERT into `agent_toolsets` with `agent_id='prism'` while the row `PRISM` still exists, we get duplicated wirings under different cases.

Steps:
1. Safety check — fail if lowercase `ako` or `hoko` pack already has rows (would mean someone did this manually already)
2. `UPDATE agent_prompts SET pack='ako' WHERE pack='AKO';` — 6 rows
3. `UPDATE agent_prompts SET pack='hoko' WHERE pack='HOKO';` — 4 rows
4. Merge `ECHO` toolset wirings into `echo` (INSERT then DELETE)
5. Merge `PRISM` toolset wirings into `prism` (INSERT then DELETE)

Output: `agent_prompts` packs all lowercase; `agent_toolsets.agent_id` all lowercase; no row count change for `agent_prompts`; minus 1 row for `agent_toolsets` (ECHO collapsed) plus 5 already-present (PRISM→prism merge).

## Rollback plan

Each migration is wrapped in `BEGIN; … COMMIT;` and idempotent via `ON CONFLICT … DO UPDATE`. To roll back any single phase:

- **Phase 5**: `UPDATE agent_prompts SET pack='AKO' WHERE agent_name IN ('ako','ako-comply',…)` — but the casing collision is back. Better: re-apply Phase 5 forward (idempotent).
- **Phase 4a**: `DELETE FROM tool_registry WHERE tool_name IN (…)` — note FK from agent_toolsets, so Phase 4b must be rolled first.
- **Phase 4b**: `DELETE FROM agent_toolsets WHERE (agent_id, tool_name) IN (…)` — list embedded in migration as a comment.
- **Phase 2**: `DELETE FROM agent_prompts WHERE pack='toro' AND agent_name LIKE 'toro-%'` (or `is_active=FALSE` if discriminator).
- **Phase 3**: `UPDATE agent_prompts SET system_prompt = <prior_value>` — Reo's migration includes prior values in a comment block for each row.
