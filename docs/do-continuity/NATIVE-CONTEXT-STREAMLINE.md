# Native context: source proposal and review boundary

The installed Mac app is unchanged. The development source now starts at one `/do/widget?nativeReview=1` workspace. A compact **Bring context** menu replaces the competing native route buttons and always-visible empty editor. Selected/copied text opens `ContextReview`; recipient verification, exact text Add and optional advanced insertion remain there. Closing/clearing invalidates the native review; committed editor text is not retracted. The page's provider consent remains a separate action.

Missing matching receiver/API is a version error, not a sign-in diagnosis. Confirmed 401 is a WebKit sign-in requirement; Chrome credentials are not copied. Lookup is metadata only, private/no-store and cookie-authenticated. Reservations are one-use, short-lived and bound to account, Personal scope, document, auth/editor generations and exact native review revision. Receipt means React committed the editor state; never saved/synced/prepared. Native-v1 neither restores nor writes the old unscoped browser draft key.

**Screenshot/photo in this source** routes to the existing Look surface without reloading or discarding writing state. It reads no image until the user selects one. WebKit file input gets a bounded PNG/JPEG/WebP chooser; preview is local, analysis still requires the existing separate confirmation. Auth/scope invalidation returns to Write and unmounts image review. Tests use an invented pixel file, never a user's screenshot. This is manual screenshot-file handling, not a native screen-grab claim or image binding receipt.

**Native one-window capture remains inactive.** `apps/do/macos/proposals/UserWindowScreenshot.swift` is an unlinked, uninstantiated macOS 14+ proposal. It presents Apple's system content picker after an explicit approved gesture, accepts one selected window, captures one frame with no audio/cursor and returns a local review image. It does not enumerate windows, start a stream, upload or infer consent. Cancel/new generation discards late callbacks. Region selection/cropping is not implemented. OS consent and private capture testing require a coordinated user session, never automatic agent execution. The image-specific owner/reservation/React-receipt contract must be separately reviewed before this adapter can be wired into Add; current text receipt is not reused as image authority.

Apple references: [content picker](https://developer.apple.com/documentation/screencapturekit/sccontentsharingpicker), [one-frame screenshot API](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager/captureimage(contentfilter:configuration:completionhandler:)), [WWDC23 system picker and screenshot flow](https://developer.apple.com/videos/play/wwdc2023/10136/). Local SDK declarations were checked. No OS screen permission or capture was exercised.

Visual proof is offscreen rendering of actual native SwiftUI source plus an isolated fictional-auth React fixture. No new visible DO instance or orb is launched during Kate's active desktop use. It is review evidence, not a claim that a matching app/web version is installed or that native VoiceOver/screen permission works end-to-end.

## Review fixes: transient work and identity

Review hashing captures the exact draft, editor revision, recipient and lifecycle generation; logout or replacement during hashing cannot restore a stale draft. Direct editor and reviewed Look context use metadata-only recipient validation before preparation, with the page session identity checked against the fresh server recipient. The existing explicit provider consent and server expected-owner checks remain required. No editor text travels in recipient lookup.

Uncertain recipient transport invalidates transfer authority and preparation consent while retaining unsent editor work. A verified logout, scope boundary or differing account clears private context. Same-owner SIGNED_IN revalidates metadata without destroying work. An accepted offer's late cancel returns its existing receipt without network validation; native verified acceptance clears pending cancellation state.

After `CI=true pnpm install --frozen-lockfile` into this checkout and a fresh workspace-local store, followed by `pnpm --filter @assembl/canvas build`, `pnpm exec tsc --noEmit --incremental false` passes with zero diagnostics (Node 22.22.2, pnpm 9.15.9, TypeScript 5.9.3). The previous nine diagnostics disappeared after installing the declared dependencies; no unrelated source changed. A baseline comparison was unnecessary because no diagnostics remained. Source-only tests do not replace an agreed live native accessibility/picker session.

Recipient resolvers report mismatch without side effects. The bridge checks its captured identity generation and request sequence before applying any destructive invalidation, so a delayed prior-owner response cannot erase fresh current-owner work. The mounted regression holds owner A metadata, switches authenticated/server identity to B, enters B text and then releases A.
