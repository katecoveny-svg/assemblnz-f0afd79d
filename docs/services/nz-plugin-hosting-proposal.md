## Existing facilities and reuse decision

**Uses:** the existing Next.js 16 / Node-compatible Vercel project and Git integration. PR1462 preview and its exact merged production deployment reached READY. The existing deployed region was `iad1`; the proposed service retains it until a regional privacy/cost decision. `vercel.json` contains existing crons and the reviewed build-ignore script. No plugin cron is required.

**Extends:** the reviewed stateless MCP SDK2 factory and strict source/tool contracts. It currently lives under `plugins/`, which `.vercelignore` excludes. Activating a route cannot simply import excluded source and assume deployment tracing will find it. A later reviewed implementation should move only the shared reviewed server/HTTP/output modules into `lib/nz-evidence/mcp/`, preserve tool definitions, and use that shared source from the development bundler. Do not expose the whole plugin subtree or alter the founder endpoint.

**Creates, inactive:** `security-proposals/nz-plugin-hosting/policy.ts` defines exact host/request limits, a default closed distributed-admission port, bounded lease-response validation and a narrow operational metric allowlist. Only tests import it. It does not execute a tool, fetch a source, resolve env, connect a database or implement distributed enforcement.

Repository rate-limit audit: `lib/creative/ratelimit.ts` counts then inserts, falling back to per-process memory; `lib/agents/chat-rate-limit.ts` counts then best-effort inserts and fails open; `lib/vessel/rate-limit.ts` reads counts and fails open. Existing paid-tool read/upsert caps are also unsuitable. These paths remain unchanged. `supabase/migrations/20260930220845_do_consumer_usage_billing.sql` provides a useful transaction/advisory-lock pattern, but its owner/subscription/billing semantics must not be reused for anonymous plugins. There is no Redis/Upstash dependency in the current root package. This audit does not prove that external account facilities are absent or that existing WAF/retention settings meet the proposal.

**Decision after resource review:** freight only in the next inactive stage. A hostname alias and clean child environment cannot isolate the parent function's project credentials or memory. Shared-project deployment remains blocked unless real function-level isolation is proved. The alternative is a narrowly scoped project on the existing Vercel platform, subject to root review and Kate's explicit infrastructure/cost approval; no project is created here. Architecture hosting remains off.

## Distributed admission and resource contract

These are proposed pilot ceilings, not a quotation, guaranteed SLA, implemented production quota or entitlement:

| Control | Proposed ceiling, across both plugin hosts unless stated |
|---|---:|
| Admitted transport requests |120/minute and2,000/UTC day |
| Active MCP requests |4 globally |
| Active public source loads/parsers |2 globally |
| Public source-load attempts |200/UTC day, failures/retries included |
| Body / serialized MCP output |1MiB /512KiB |
| Admission RPC wait |1second |
| Request body + handler |10seconds total |
| Platform execution termination |15seconds |
| Lease expiry |20seconds, longer than proved platform termination |
| Source download/body |8seconds total |
| Parser worker |3seconds, forcibly terminate on deadline |

Every admitted initialize/list/ping/call counts, including client retries. User-selected JSON-RPC IDs never become idempotency keys. The server generates an invocation UUID; exact duplicate backend claims cannot mint another lease or execute again. No request or response is persisted for replay. Limits are denied with fixed429/Retry-After; closed, timeout, malformed result or uncertain transaction returns503. No fail-open or per-process fallback. Current per-process4/60 guards remain an additional backstop, never the global authority.

`security-proposals/nz-plugin-hosting/quota-review.sql` is an **unexecuted, unapplied** quota-only transactional proposal. It creates a private schema, disabled control, bounded current-window counters and UUID/fenced leases with a48-hour cleanup cutoff on successful claim paths. This is not a48-hour deletion guarantee while idle, denied or disabled. A separately reviewed independent cleanup/monitor mechanism, bounded work and overdue-row alerts must be proved before activation or any retention promise. A NOLOGIN owner owns only these objects; a separate quota role has only schema usage and three fixed RPCs. No content, user/customer identity, billing entitlement, broad service credential or Data API exposure is proposed. Functions use qualified relations, explicit pg_catalog-first search_path with pg_temp last and qualified built-in types/functions, revoked PUBLIC/anon/authenticated permissions and100ms lock timeouts. A future scoped connection must prove pool4 and500ms statement deadlines. No schema, role, grant, credential or setting was created.

One control-row lock serializes claims. Database clock is sampled after locks and refreshed before return; duplicate invocation IDs deny rather than replay a lease. Source claims lock the parent row, resample time after its lock and cap actual child expiry at parent expiry. Late issuance rechecks the full15-second minimum and returns the actual capped interval. The pure interval regression is not database lock proof. Adversarial temporary-schema type/function/relation shadowing and parent expiry/lock-wait tests remain mandatory before any runtime grant. Release is fenced and never refunds counters. `checkedClaim` subtracts full monotonic RPC elapsed from the database-issued interval and requires at least15seconds remaining. Regressions cover expired-in-transit,1ms leases, delayed issuance, impossible ordering, clock regression and exact minimum lifetime. Database concurrency/privilege/clock behaviour still requires authorised disposable-runtime proof. [Supabase function security](https://supabase.com/docs/guides/database/functions), [Postgres locking](https://www.postgresql.org/docs/current/explicit-locking.html)

Rejected work is also bounded locally:60 total admission attempts/minute and4 in flight, including denial/timeouts; every caller wait has a1second deadline. Noncooperative backend calls retain their four capacity slots until actual settlement; cancellation alone never frees them. The single log-call slot likewise remains occupied across minute windows until real settlement. SQL counts attempted work before eligibility,480/minute. Rejection summaries saturate fixed counters, request at most one global log slot/minute/process with a1second deadline, and emit nothing on denial/error/timeout. SQL grants at most10 summary slots/minute. These bounds do **not** prevent every anonymous request from invoking a serverless function or reaching a denial RPC across replicas. Global flood invocation costs remain unproved and block public activation; success quotas alone are not a spending guarantee.

The closed adapter and local tests specify failure behaviour only. Before rollout, prove concurrent claims across independent replicas, minute/day boundary bursts, duplicate/lost response/timeout cases, release fencing, DB lock/statement deadlines, quota exhaustion and restore/cleanup safety against a disposable authorised test database. No production SQL was executed. The exact proposal was applied only inside a task-owned PostgreSQL17 Docker container with network none, no host data mounts,256MiB memory and0.5CPU; the container was removed after proof. Twenty-three specific actual checks passed: disabled gate, existing/future-function permissions, eight-replica admission with fail-closed100ms lock timeouts, child/parent expiry, released parent, parent/control row locks, temporary-schema/operator attacks, duplicate races, fencing/no-refund, parent release held until child release,70ms parent transaction margin loss, final expiry recheck after70ms counter work, pg_cancel_backend and cleanup threshold. The executable script and proof JSON are in the review artifact. This is not production-version, network-driver cancellation, independent cleanup scheduler or platform deployment proof. The September2026 Supabase changelog contains PostgreSQL minor-release changes; this proposal introduces no affected extensions/operators and does not attest to the production database version. [Supabase changelog](https://supabase.com/changelog)

Proposed edge flood rule: exact two hostnames AND path `/mcp`, per-IP60requests/60seconds, deny/429 with no CAPTCHA/browser challenge; a separate bounded rule for each challenge path. Check plan entitlement, actual rule semantics, trusted platform IP handling and OpenAI connectivity before publishing any rule. Anonymous OpenAI callers may share egress IPs, so IP throttling is flood protection, not per-person fairness. Vercel documents rate-limit counters as per-region; a constant key in its SDK does not establish a strict cross-region global ceiling. The database contract supplies that boundary. No firewall SDK is added. [Vercel rate-limit SDK](https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting-sdk)

An offline bounded parser proposal now uses a fixed worker entry,3second SIGKILL deadline, abort handling,12MiB stdin/512KiB stdout limits and explicit clean child environment. It parses only supplied allowlisted snapshots through the reviewed source projection; network fetch is disabled. Tests prove actual child termination and safe errors. A held public tariff snapshot (4,648,033bytes, SHA256 `2baf2e34401d75378578afe45f04f2f17c245de7a7f6a4bc97f457fa43b8e46d`) completed offline in594ms with peak RSS461,438,976bytes (~440MiB). This is a measurement, not an OS-enforced512MiB ceiling or deployed-platform proof. Two such workers could consume ~880MiB before parent overhead.

A separate native-memory fixture with16MiB heap and64MiB Buffer reached ~106MiB RSS, proving heap flags do not bound archive/native memory. A clean child does not remove credentials from a shared parent Vercel function. Release requires actual whole-function memory/CPU limits, combined concurrency headroom, child termination by15seconds, environment isolation and no secret propagation. Post-execution RSS rejection is not a hard allocation limit. If these cannot be proved, remain closed.

## Source freshness and cache

Reuse fixed credential-free Customs endpoints, redirect-denied fetches and current allowlisted projections. No shipment/RFI/identity values are sent upstream. Compressed tariff8MiB, expanded archive96MiB, details32MiB, XML8MiB; preserve strict schema/member/checksum/XML/date admission. Index once per admitted process snapshot. Tariff cache1hour, FX24hours, at most2 local flights; only fully admitted snapshots become visible. Failed200/parsing admissions have5second negative backoff, not a positive cache TTL. No fixture, stale last-known or market fallback.

Producer daily04:00Pacific/Auckland plus four-hour grace remains an assembl engineering policy. Tariff usable expiry is min(fetch+24hours, next08:00Auckland producer-grace boundary), DST-aware; separate fetchExpiresAt/usableUntil remain explicit. Full numeric-code quarantine covers reversed day/minute intervals. Global source quota exhaustion returns unavailable even if the private process has no cache; it cannot trigger extra downloads. Cache is public source data only, in-process and lost on instance recycle. A shared public-snapshot store could reduce repeated downloads but needs separate rights, retention, cost and access approval; none is proposed as a silent default.

## Logging, privacy and support drafts

No raw body/output, user question/document/evidence IDs, JSON-RPC ID, IP, email, cookies, token, query URL, exception text or stack is accepted. `operationalEvent` rejects extra fields rather than redacting arbitrary objects. Metrics retention proposal24hours, aggregate counters/UUID lease tombstones target48hours, not enforced independently while idle/disabled; no personal-IP application bucket is required. Durable control/quotas do not store user content.

This does not imply Vercel/WAF/support/ChatGPT retain nothing. Before release, inventory real access/error logs, traces, replay/analytics/APM integrations, request URLs and upstream/SDK error handling. Disable request/response capture for these exact hosts/paths, disclose unavoidable provider IP/network metadata and actual retention/location/subprocessors, and verify with distinctive fictional markers. Avoid custom proxy headers in logs. Access logs and vendor backups may require different documented retention than application metrics; do not promise deletion periods without proof.
