## Direction and proposed copy

One DO personal workspace: **“DO, your New Zealand personal assistant.”** Main question: **“What would you like done?”** Supporting line: **“Bring a question, a plan or the thing on your mind.”** Primary modes **Write / Talk**, supporting **Add photo/file**. The integrated action should use the existing explicit preparation/consent path; the standalone preview says **Add to tasks** because it only creates a local draft.

Three optional ideas: **Plan this week’s shop**, **Organise a weekend away**, **Review my bills**. Shop/Travel/Save describe capabilities, not competing agents. Bills remains available as an outcome and under existing tools. No persistent People/Business chooser inside the workspace. The two offers belong in commercial/onboarding context. One task list below with All / Today / Needs you; show real state and empty states, never illustrative history disguised as an account.

Later expanded-workspace organisation may use **Today** (briefing/tasks/approval), **Household** (people/pets/vehicles/properties), **Money** (Shop/Save/Bills and opted-in watches). This grouping is proposed, not implemented; it must not crowd the widget. Distinct homes/regions and family profiles require owner/member permission, purpose, retention/deletion, edit/revocation and source-level access. Home-loan offers, power/solar and efficiency radar need opt-in cadence, licensed current sources, cost/eligibility assumptions, change thresholds and stop controls. No background watcher, personal financial profile, medical upload or secure vault is created here. Travel remains an intent/task journey rather than a fourth competing workspace.

The glass D stays visible in header/launcher and as a smaller desktop accent. Instrument Sans carries the interface; IBM Plex Mono identifies actual draft/review state. Paper/chalk, visible plum ink, rose focus, quiet rules and whitespace replace the oversized split hero and separate sample card. Task insertion is the only authored motion, removed under reduced motion. Mobile keeps the input foremost and removes the decorative hero image.

Secondary More contains account/settings integration in the eventual product, Install, Privacy and **Tools & examples**. Retain Builder DO, Bills/CSV, Household, Meetings and Messages routes. Technical NZ-reference options belong in a contextual disclosure close to their explicit consent action—not silently checked or removed from the provider boundary. The static preview has no provider path and therefore no fake consent checkbox.

## Draft integration sequence — exact component seams

This is the implementation sequence for this entry slice, not a competing programme roadmap. Root's consolidated roadmap and the reliability owner's state contract govern release order. No runtime edits are included in this commit.

1. **Shared navigation, no state migration.** Extract `components/do/DoSecondaryNavigation.tsx` from the current menus in `app/do/personal/PersonalDo.tsx` and `components/do/DoProductFrame.tsx`. Accept the existing account controls/return URL and embedded link behaviour as inputs. Keep Install/Privacy and route-compatible Tools & examples. Do not fabricate an account state or force a sign-in recheck. Validate every retained route and return target, keyboard disclosure behaviour and embedded pop-out semantics.
2. **Controlled entry chrome.** Introduce `components/do/DoEntryChrome.tsx` with a small CSS module for heading, Write/Talk controls, contextual attachment action and optional starter slots. Keep draft values and voice admission outside this component. Render it from `LifeAdmin`/`PersonalDo` and `DoFocusWorkspace`; leave `DoHome`, `/do/personal`, `/do/widget`, PWA start URL and native query compatibility intact. Port the reviewed typography/spacing from the prototype, not its mock task/voice code.
3. **Preserve mounted editors and explicit handoff.** `PersonalDoAssistant`, `DoTextWorkspace`, `LifeAdmin` and `DoGeminiLive` retain their existing handlers and consent fields. Switching visual entry must not recreate a keyed editor, reset text, bypass `talk.canOpen`, replace an admitted voice session or automatically start media. Owner change remains the intentional privacy-clear/remount boundary. Keep `useDoCompanionEntry`, native account/document/revision receipt checks and the iframe/full-window limitation. Carry unsubmitted text between genuinely different engines only through an explicit reviewed offer; never silently transfer it to a different surface or account.
4. **One list using existing outputs, after state-owner agreement.** Define a presentation-only `DoTaskListItem` contract and project real existing records into `components/do/DoTaskList.tsx`: origin + ID, owner scope, title, created/updated time, revision, state, next action, storage scope, and evidence link. Each row opens its owning workflow; preparation/review remains distinct from execution. Empty means empty. Do not write all record types into a new localStorage key. Reliability owner decides conversation/task identity and persistence/recovery before cross-device claims or migration.
5. **Input/tool access stays truthful.** The integrated Upload affordance offers only currently supported, reviewed image intake first; PDF/general-file modes require verified parsing, size/MIME controls and provider disclosure. Existing reference consent moves into a contextual disclosure without changing its value/default/payload. Optional Shop/Travel/Save starters must not overwrite a nonempty draft or submit. Public-data/AT invocation is a later safe tool-routing slice; broad web search, email/calendar, bookings, clinical decisions and vault are not UI work.
6. **Adapt the existing launcher last, with progressive expansion.** Root’s screenshot review found the initial prototype widget too tall: it repeats the full heading and list. Integrate a smaller default with the glass D, a short question, Write/Talk, a short editor and Add photo/file; keep outcome starters and task list behind an explicit Expand / View tasks action. The full workspace retains the expanded composition. Do not dim, block or cover most of the user’s page, force a modal focus trap, or open a large panel automatically. Closing/expanding preserves the mounted editor. Update `apps/do/shared/distribution.ts` while retaining its reviewed-context/postMessage rules and live mounted iframe. Keep Talk's supported full-window launch. Native Swift chrome/install and extension permission changes remain separate owners; a website widget redesign cannot establish new native reach.

Acceptance on the actual integration: relevant existing `PersonalDo.interruption.test.ts`, `PersonalDo.storage.test.ts`, LifeAdmin, profile/session, companion-entry, native handoff and Gemini tests; complete request → consent → prepare → edit/review and failure/cancel/retry paths; no auto mic/network submission on entry; sign-in stays valid; anonymous/account A/account B and expiry transitions; refresh/storage-unavailable recovery; desktop/375px/embedded/native-query layouts; keyboard/focus/reduced motion; actual production build/typecheck/lint/brand/macron checks.
