## Privacy and continuity

`/api/do/personal` returns the server-verified workspace identity even on authenticated storage errors. Settings, calls and local checklist state remount on account changes. Auth events invalidate pending reads before server revalidation; delayed previous-owner responses are ignored. Browser snapshots are opt-in, UUID-namespaced and owner-checked; legacy global snapshots are never loaded. Guest snapshots are disabled. The interface warns that browser storage is not encrypted or a defence against someone inspecting the same browser profile.

Guests can download all current work before signing in/leaving, and receive an explicit navigation warning. There is no silent guest-to-account transfer. Pending external shares survive guest sign-in until accepted into a checklist; previous-account shares are discarded. Share links are never automatically opened or fetched. No source content is placed in navigation URLs.

Profile deletion removes saved account settings, not previous provider requests or responsibility records. Changing settings ends any existing call and requires new consent. The responsibility scheduler, quotas and seven-day consent remain unchanged; its first real scheduled run is a separate proof item.

## Setup and rollout

Apply `supabase/migrations/20260930031622_do_personal_profiles.sql` to the intended environment before account-storage proof. It was generated by the official CLI and tested locally, **not applied to production**. It is additive, RLS-enabled and service-write-only. Missing profile storage yields an honest 503; existing responsibilities continue without personalised style.

Uses existing Supabase environment variables and voice requirements: `DO_GEMINI_LIVE_ENABLED=true`, `GEMINI_API_KEY` or `GOOGLE_GENERATIVE_AI_API_KEY`, plus the existing durable allowance store. No credentials were created, copied or exposed. Local checklists and the public feed require no model key.

Email/calendar monitoring, real inbound forwarding addresses, shared household accounts, bank/utility/school/health/government account access, automatic payments/bookings/submissions, push reminders and native iPhone installation remain unimplemented or separately dependent on permissions/providers. Official links are labelled as links, never connected accounts.
